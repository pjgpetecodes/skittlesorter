Part 6: Fail safely and repeat the demonstration

Release baseline, reviewed 30 October 2026: latest GA agent release inspected: 1.4.0, 25 June 2026; Azure IoT CLI 1.0.0b2, 6 October 2026. Sorter 1.0.0/1.1.0 are demonstration build versions, not published releases. Draft: automated local tests are distinct from outstanding physical-Pi failure demonstrations.

A successful update is only half the demonstration. Run these scenarios first with mock hardware and a known-good prior release, then repeat applicable cases on an attended, safe Pi setup.

Use the installer's documented recovery command after interruption. Never manually delete the journal to turn an unresolved transaction into success. Keep the prior healthy release until the update and reboot evidence are complete.

The GA script handler's adapter reports actual local installer failures. Its is-installed check uses release metadata, while transaction health verification checks running readiness. Cloud-initiated rollback policies are a separate service feature; they do not replace the local installer's immediate safety rollback.

Preserve the interesting evidence

Compare protected configuration/certificate checksums before and after each exercise. Verify the selected release, readiness process/version, service logs and resumed telemetry. If the previous release cannot become healthy, leave a visible operator-action-required state instead of claiming either version succeeded.

Power loss and actual motor dynamics are not reproduced by mocked process tests. The checked-in test suites document local automated coverage; physical power-interruption evidence remains a separate acceptance gate.

Reset and clean up deliberately

To repeat the demonstration, explicitly reinstall the known-good baseline using the trusted installer and verify it before submitting another deployment. Use new cloud deployment IDs. Do not edit the installed-version marker by hand.

Stop update controllers before switching to the ADR lab. Keep only one mechanism in charge of the sorter. Cleanup should target only the new tagged GA resource group after reviewing its contents and stopping its devices; never delete the original ADR lab to make this tutorial work. No script here deletes cloud resources automatically.
